## Shared Patterns

### Integration test base class
**Source:** `WorkdayIntegrationTest.kt` (lines 20–45)
**Apply to:** `EventServiceTest.kt`

All service integration tests extend `WorkdayIntegrationTest`. This wires up the full Spring context with `@SpringBootTest`, activates the `"test"` profile (H2 in-memory DB), and runs `cleanupDbService.cleanup()` after every test. No `@Transactional` needed at test class level.

### BudgetAllocation type assertions
**Source:** `BudgetAllocationPersistenceTest.kt` (lines 43–70 for assertIs pattern; lines 161–164 for multi-type filter)
**Apply to:** `EventServiceTest.kt`

Use `assertIs<HackTimeBudgetAllocation>(x)` / `assertIs<StudyTimeBudgetAllocation>(x)` (from `kotlin.test`) to assert on the runtime type. Use `filterIsInstance<T>()` to separate time allocations from money allocations.

### Deletion via budgetAllocationService (not type-specific services)
**Source:** `EventService.kt` lines 175, 216, 332
**Apply to:** `syncBudgetAllocations` fix in `EventService.kt`

Always delete via `budgetAllocationService.deleteById(it.id)` — not `hackTimeBudgetAllocationService` or `studyTimeBudgetAllocationService`. This is consistent with all existing deletions in the same method.
