# Phase 18.1: Close gap ALLOC-04 — swap allocation type on event type change - Context

**Gathered:** 2026-05-22
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix a single backend bug in `EventService.syncBudgetAllocations`: when an event's `defaultTimeAllocationType` changes (e.g., FLOCK_HACK_DAY → CONFERENCE triggers HACK → STUDY), existing time allocations for all persons must be deleted and recreated as the new type. Currently the `when (existingTime)` block updates allocations in-place, silently keeping the wrong entity type.

Frontend is unaffected — the dialog already reads `budgetAllocations[]` from the event response and reloads after save.

</domain>

<decisions>
## Implementation Decisions

### Type Swap Mechanics (Backend)

- **D-01:** Fix is entirely in `EventService.syncBudgetAllocations` (`workday-application/src/main/kotlin/community/flock/eco/workday/application/services/EventService.kt`). No frontend changes needed.
- **D-02:** Replace the `firstOrNull { it is HackTimeBudgetAllocation || it is StudyTimeBudgetAllocation }` approach with: find ALL time allocations (both `HackTimeBudgetAllocation` and `StudyTimeBudgetAllocation`) for this person+event, delete them all via `budgetAllocationService.deleteById(id)`, then create exactly one new allocation of the correct type with hours recalculated from event data.
- **D-03:** A person CAN legitimately have both a `HackTimeBudgetAllocation` and a `StudyTimeBudgetAllocation` for the same event. The delete-all-then-recreate approach handles this correctly without special-casing.
- **D-04:** Use `budgetAllocationService.deleteById(id)` for deletion — this is the existing pattern used in the same method for other deletions (lines 175, 216, 332).

### Test Layer

- **D-05:** Both Kotlin unit test AND Playwright e2e test are required (user explicitly confirmed both).
- **D-06:** Kotlin unit test: create a new `EventServiceTest.kt` at `workday-application/src/test/kotlin/community/flock/eco/workday/` alongside existing `EventControllerTest.kt` and `EventRepositoryTest.kt`. Test the type-swap scenario directly on `syncBudgetAllocations`.
- **D-07:** Playwright e2e test: change event type in the UI, save, verify the budget allocation list shows the new type.

### Frontend

- **D-08:** No frontend changes. The budget management dialog already reads `budgetAllocations[]` from the event response (`GET /api/events/{code}`). After save it reloads the event and shows the updated allocations.

</decisions>

## Existing Code Insights

### Reusable Assets
- `budgetAllocationService.deleteById(id)` — already used in `syncBudgetAllocations` for person-removal cleanup (lines 175, 216) and money allocation removal (line 332). Same pattern applies for type-swap deletion.
- `hackTimeBudgetAllocationService.create(...)` / `studyTimeBudgetAllocationService.create(...)` — already used in the "create new" branch (lines 282, 293). Reuse for recreation after delete.
- `buildDailyTimeAllocations(event)` — already builds the correct per-day hours from event data. Use this (not stale allocation data) when recreating.

### Established Patterns
- `existingByPerson[appPerson.uuid]` — groups all allocations by person UUID. Currently used with `firstOrNull`; change to `filter { it is HackTimeBudgetAllocation || it is StudyTimeBudgetAllocation }` to get ALL time allocs for the person.
- Deletion pattern: `budgetAllocationService.deleteById(it.id)` (not type-specific services).

### Integration Points
- `syncBudgetAllocations` is called on every create/update of an event (lines 105, 119, 143, 167). The fix runs automatically whenever the event is saved.
- The `isHack` / `allocType` / `typedDaily` variables already computed above the `existingTime` block remain valid — no changes needed to those.
