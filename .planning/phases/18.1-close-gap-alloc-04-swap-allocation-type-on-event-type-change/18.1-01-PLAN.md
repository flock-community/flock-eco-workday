<objective>
Fix the ALLOC-04 bug in `EventService.syncBudgetAllocations`: when an event's `defaultTimeAllocationType` changes, the existing in-place `update` keeps the wrong entity type. Replace the single-match update branch with a delete-all-then-recreate flow so the resulting allocation always matches the current event type.

Purpose: Close gap ALLOC-04 — Changing the budget type on an existing event must update all existing time allocations to the new type.
Output: Modified `EventService.kt` whose `syncBudgetAllocations` produces exactly one time allocation of the correct concrete type per participant after every save, even when both `HackTimeBudgetAllocation` and `StudyTimeBudgetAllocation` previously existed for that person+event.
</objective>

| T-18.1-03 | Denial of Service | Unbounded delete loop | accept | Loop iterates over per-person time allocations, bounded by the number of time-allocation rows for one person+event (in practice <= 2 per D-03). Same bound as the existing money/person cleanup loops in the same method. |

| T-18.1-05 | Repudiation | Audit of allocation deletes | accept | Deletes go through the same `budgetAllocationService.deleteById` path already used for person-removal and money-removal in this method. Logging/auditing behavior is unchanged. |
