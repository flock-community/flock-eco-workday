## Detailed Findings

### Orphaned Exports

**1. `generateDefaultAllocations` — `eventBudgetTransformers.ts`**

- Exported, imported in `eventBudgetTransformers.test.ts` (33 test calls).
- **Never imported or called in any production `.tsx`/`.ts` file.**
- Phase 15-01 SUMMARY claims "Modified handleSubmit with two-path approach: Path A uses manual customizations (budgetsDirtyRef), Path B auto-generates defaults." The current `EventDialog.tsx` `handleSubmit` has neither path — it only calls `EventClient.put/post(eventData)`. The backend `EventService.syncBudgetAllocations` handles all allocation creation atomically.
- **Assessment:** The function is production-dead. ALLOC-01/02/03/05 are fulfilled by the backend, not this helper. The SUMMARY documentation describes an architecture that no longer exists.

**2. `diffAllocations` — `eventBudgetTransformers.ts`**

- Exported, imported in `eventBudgetTransformers.test.ts` only.
- **Never called in any production file.**
- Same root cause as above: original design had frontend diffing allocations and issuing individual create/update/delete API calls; the actual implementation delegates entirely to the backend.

### Architecture Clarification (Phase 15 Design Drift)

The Phase 15-01 SUMMARY describes a "two-path handleSubmit" frontend approach. The production `EventDialog.tsx` reflects a different (simpler, better) architecture: **all allocation sync is backend-driven via `EventService.syncBudgetAllocations`**, called on every create/update/subscribe/unsubscribe. The frontend only submits the event form fields (`description`, `from`, `to`, `days`, `budget`, `type`, `defaultTimeAllocationType`, `personIds`). Requirements ALLOC-01 through ALLOC-05 are all met — through the backend, not through the frontend helpers the SUMMARY describes.

### Warnings

**WARNING-01 — Backend/frontend money-gate mismatch (ALLOC-03 / Phase 15-02)**

- Frontend `EventBudgetManagementDialog.tsx` gates `showMoneySection` on `type === FLOCK_HACK_DAY || CONFERENCE` (line 92).
- `EventBudgetSummaryBanner` gates via `EventTypeMappingToDefaultBudgetType[eventType] !== null` (same two types).
- Backend `EventService.syncBudgetAllocations` has **no event-type gate on money allocations**: it creates `StudyMoneyBudgetAllocation` for any event where `budget > 0 && persons > 0`, regardless of event type.
- `EventForm` does not zero the budget field when switching to `GENERAL_EVENT` or `FLOCK_COMMUNITY_DAY`.
- **Consequence:** An admin who sets `budget > 0` on a `GENERAL_EVENT` will have money allocations created in the backend that are invisible in the UI. Not a blocker for normal workflow (these types default to `budget=0` and UI auto-sets `defaultTimeAllocationType=null`) but is an inconsistency if an admin manually edits the budget field.
- Affected requirements: ALLOC-03 (partial — no type gate enforcement on backend).

**WARNING-02 — UI-01 button label mismatch between SUMMARY and source**

- Phase 17-01 SUMMARY states: "`BudgetAllocationFeature.tsx` lines 162-166 already contain `<Button><AddIcon/> Add</Button>` — identical to ProjectFeature."
- Actual source (`BudgetAllocationFeature.tsx` line 150): `<AddIcon/> Add Study Money`
- `ProjectFeature.tsx` line 57: `<AddIcon /> Add`
- The texts differ. The Playwright UI-01 test passes because `getByRole('button', { name: 'Add' })` uses substring/contains matching and "Add Study Money" contains "Add". The test does not verify the button label is exactly "+ Add" as the SUMMARY claims.
- **Consequence:** UI-01 is marked Complete and the test passes, but the button label does not match the site-wide pattern if "Add" (not "Add Study Money") is the intended pattern. The requirement text says "uses `+ Add` pattern matching other resource pages" — this is not met.
- Affected requirements: UI-01.

**WARNING-03 — Phase 14 BUG-01 fix is superseded**

- Phase 14 added `useCallback` with `[]` deps to `handleBudgetStateChange` in `EventDialog.tsx` and removed `onBudgetStateChange` from the child `useEffect` dep array.
- Current `EventDialog.tsx` does not pass `onBudgetStateChange` to `EventBudgetManagementSection` at all (prop is optional and absent at the callsite).
- The Phase 14 fix is effectively inert — the callback was removed entirely in the subsequent architectural refactor. BUG-01 cannot recur because the triggering callback no longer exists.
- **This is safe**, but the SUMMARY is misleading about which fix is in production.

**WARNING-04 — EVNT-07 full e2e run deferred; TypeScript-only verified**

- Phase 18.1 SUMMARY: "Full e2e run: NOT executed — requires running backend." EVNT-07 is TypeScript-verified and structurally sound, but has never been run against a live backend/frontend.
- Cross-suite ordering is safe (workers:1, EVNT-07 in the same file as EVNT-01 which creates the required event).

## Regression Assessment

**18.1 delete-all-then-recreate does NOT break ALLOC-01:**
`syncBudgetAllocations` always recreates exactly one time allocation per person (after deleting existing). The `if (event.defaultTimeAllocationType != null)` guard ensures no-op for events without a default type. No regression.

**18.1 does NOT break 15-02 money-type gate:**
Money allocation block in `syncBudgetAllocations` (lines 274–298) is untouched by the 18.1 ALLOC-04 fix. The `existingTimeAllocations.forEach(deleteById)` only targets `HackTimeBudgetAllocation` and `StudyTimeBudgetAllocation`. Money allocations are handled separately. No regression.
